这个小应用没有任何新技术，用的全是前 3 课的东西： 查找元素、创建节点、事件委托、表单取值。 它演示的是组织方式 —— 界面 = f(数据)。

    页面上所有内容都由一个数组 todos 决定。 勾选、删除、新增、筛选，每个操作都只做一件事：改数组。 改完调用 render()，整个列表按最新数据重新画一遍。 

    事件  →  改数据  →  render()  →  界面更新

永远不要：事件  →  手动去改某一行的文字

    数据变了就整体重画，看起来"很浪费"，但界面永远不会和数据对不上 —— 你不需要记住"删数据的时候还要顺手把 DOM 也删掉"。 当页面变得复杂时，这种写法省下的心智负担远大于性能开销。 React 的核心就建立在这一点上（界面 = f(数据)）， 之后再去看 React_learn 会顺很多。

    数据会存进 localStorage：刷新页面、关掉再打开，内容还在。 想清空就点"恢复默认数据"，或者在 Console 里执行 localStorage.clear() 再刷新。

# 开发文档

《开发文档》按主题拆成 6 篇。**每篇里的 `§X.Y` 编号是稳定 ID，不是排序号。**

## 为什么编号不连续

`§X.Y` 不只在文档内部互相引用——**源码注释直接引用它**，约 40 处、分布在 11 个文件里
（`App.tsx` 引 §6.2 / §6.3 / §6.5 / §7.3，`lineOption.ts` 引 §6.4 / §6.5 / §6.6 / §10.3，
`bootstrap.ts` 引 §3.2.0……）。

所以编号是**冻结的**：删掉的小节留空号、不重排——§3 现在是 `§3.1`（已删）→ `§3.2` → `§3.3`，
中间不会被补上一个新号。空号不是漏洞，是**已注销的编号**，下面第二张表记着它们原本是什么。

跨文件引用一律写成纯文本 `§X.Y`，**不做 markdown 锚点链接**：中文标题经 GitHub / VS Code /
其他渲染器生成的 anchor 规则不一致，锚点迟早烂掉；编号本身才是那个稳定的东西。

## 一条写作约定：不誊抄代码已经声明的事实

这次整理反复撞见同一个毛病——**凡是文档把代码里的事实誊抄了一遍的地方，后来都烂了**：

- §2 抄了指标清单 → 写「约 25 个」，实际 10 个
- §3.3 抄了 schema → 画了 8 张表，实际 4 张
- §4 抄了依赖表 → 列了 React Router、Zustand、TanStack Query/Table、Radix、SheetJS、date-fns、
  electron-log、Playwright、ESLint/Prettier 十项，**一项都没装**
- §6.2 抄了一份 8 槽位的分类色表 → 代码只取用槽位 1，**另外 7 个色值从未被任何一行代码引用**，
  连带给它们做的 CVD 校验也成了无处可依的数字

反过来说，**§6 的规则部分一直没坏**——「线宽 2px」「不要垂直网格线」「绝不双轴」写的是
**规范**（图该长什么样），不是从代码里摘出来的清单，所以代码怎么变它都不烂。

**能写规范就写规范，写不了规范就指向事实源——两条路都不要重新誊写。**

| 事实 | 事实源 |
|---|---|
| 指标元数据（有哪些指标、口径、单位） | `src/shared/indicators.ts` |
| 表结构 | `src/main/db/schema.sql` + `src/main/db/migrate.ts` |
| 装了哪些依赖 | `package.json` |
| IPC 契约 | `src/shared/types.ts` |
| npm scripts | `package.json` |
| 图表色值 | `src/renderer/src/styles/index.css` 的 `--c-*` 变量 |

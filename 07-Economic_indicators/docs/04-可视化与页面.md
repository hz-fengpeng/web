## 6. 可视化设计规范

> ⚠️ **本节是规范性规范**——源码注释以 `§6.x` 引用它来约束图表的画法。

> **目前只有一种图表：单序列折线图**（`charts/lineOption.ts`），所以本节只写它用得到的部分。
> 做出来之前不写它的规范；真要做别的形式时，先补 §6.1 的形式选择，再写它的 marks 规范，

### 6.2 配色系统

#### 序列色

分类色**只有槽位 1 在用**（单序列折线就是这一个）：`--c-accent`，浅色 `#2a78d6` / 深色 `#3987e5`。

**固定顺序，按序分配，绝不循环。** 浅色 / 深色两套是同一批色相针对各自表面重新取阶的结果，
不是简单反转——`--c-accent` 的深色值 `#3987e5` 就比浅色值更亮，正是为深色表面重新取的阶。

**出现第二个序列时不要顺手编一个新色相。** 先扩这张表、跑一遍色觉障碍（CVD）校验，
代码再取用。校验口径：ΔE 取 OKLab 欧氏距离 ×100，相邻对 CVD 目标 **≥ 8**、
正常视觉硬门槛 **≥ 15**；若两个 mark 可能任意相邻（散点、地图类），改用更严格的 all-pairs 检验。

> 原表列到槽位 8，附一整张相邻对校验结果。槽位 2–8 的 14 个色值里，**只有槽位 8 的深色值
> `#e66767` 活了下来**——它被沿用为深色的 `--c-up`（见 §6.3 的表）；其余 13 个从未进入过
> `src/`。校验结果也只对那批已删的色值成立，一并删除。
> 原内容见 `git log -- docs/开发文档.md`。

#### 状态色（固定，不随主题变化）

| 用途 | 色值 | 浅色表面对比度 | 深色表面对比度 |
|---|---|---|---|
| good | `#0ca30c` | 3.27 | 5.19 |
| warning | `#fab219` | 1.79 | 9.49 |
| serious | `#ec835a` | 2.57 | 6.60 |
| critical | `#d03b3b` | 4.68 | 3.62 |

**状态色永远搭配图标 + 文字标签**，绝不单靠颜色传达状态——`App.tsx` 的 `HealthDot` 就是这个
形状：`● 正常` / `◐ 部分指标失败` / `▲ 采集失败` / `○ 未采集`，颜色只是第三条通道。
浅色模式下 warning 和 serious 天然低于 3:1，图标 + 标签就是这个设计的补偿手段。

#### 框架与文字色

| 角色 | 令牌 | 浅色 | 深色 |
|---|---|---|---|
| 页面底板 | `--c-canvas` | `#f9f9f7` | `#0d0d0d` |
| 图表表面 | `--c-surface` | `#fcfcfb` | `#1a1a19` |
| 主要文字 | `--c-ink` | `#0b0b0b` | `#ffffff` |
| 次要文字 | `--c-ink-2` | `#52514e` | `#c3c2b7` |
| 弱化（坐标轴/刻度） | `--c-ink-muted` | `#898781` | `#898781` |
| 网格线（hairline） | `--c-grid` | `#e1e0d9` | `#2c2c2a` |
| 基线 / 坐标轴 | `--c-axis` | `#c3c2b7` | `#383835` |
| 边框 | `--c-hairline` | `rgba(11,11,11,.10)` | `rgba(255,255,255,.10)` |

> **文字永远穿文字色，不穿序列色。** 数值、标签、图例一律用上表的文字色；身份由旁边的色块承载。

### 6.3 涨跌配色决策（本产品的特殊问题）

中国金融惯例是**红涨绿跌**，与欧美完全相反。但红绿恰恰是色觉障碍（红绿色盲，人群中约 8% 的男性）最难区分的一对。

**处理方案：**

1. **默认遵循中文用户习惯：红涨绿跌。**（国际惯例的绿涨红跌切换**尚未实现**——没有设置页）
2. **无论选哪种，涨跌必须三重编码：数值 + 符号/箭头（▲▼）+ 颜色。** 颜色绝不单独承载涨跌含义。
3. 涨跌色**不占用分类色槽位**——它是独立的一组语义色，不参与 6.2 的序列色序。
4. 表格视图中，涨跌列始终带 `+` / `−` 符号。

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--c-up`（涨） | `#d03b3b` | `#e66767` |
| `--c-down`（跌） | `#0ca30c` | `#0ca30c` |

> 这是本产品在无障碍与本地习惯之间的关键权衡。遵循本地习惯是必要的（否则用户会读反），但必须用符号和数值兜底，让色觉障碍用户同样能准确读取。

### 6.4 图表规范（marks）

- **线宽 2px**；数据点标记直径 **≥ 8px**
- **重叠的 mark**：加 **2px 表面色描边环**（`--c-surface`——交叠处才分得开）
- **网格线**：hairline，弱化处理；**不要垂直网格线**（时间序列的 x 轴网格通常是噪音）
- **坐标轴**：只保留基线，不要边框盒子
- **标注**：**选择性直接标注**关键点，不要每个点都标数字
- **图例**：≥ 2 个序列**必须**有图例；≤ 4 个序列同时做直接标注；**单序列不要图例框**（标题已经说明了它是什么）
- **字体**：全程系统无衬线，不使用装饰性字体。**字体栈的事实源是 `styles/index.css` 的 `--font-sans`**，不要在这里再抄一份（本节原先抄的那串就与代码不符：多了 `system-ui` / `Segoe UI`，少了 `BlinkMacSystemFont` / `Helvetica Neue`）。坐标轴与图例是 canvas 画的、不会从 DOM 继承字体，必须显式传给它（`charts/theme.ts` 的 `sans` 字段）。
- **数字**：hero 数字与表格各列**用等宽数字**（`tabular-nums`，即 `styles/index.css` 的 `.tnum`）——数值会随选中指标变化，比例数字会让整块布局左右跳动。⚠️ **坐标轴刻度做不到这件事**：`.tnum` 是 DOM 的 `font-variant-numeric`，而刻度是 ECharts 在 canvas 上画的文字，不继承 DOM 字体特性，全仓也没有对应的 ECharts 设置。这条目前只对 hero 与表格成立。

### 6.5 交互规范

- **折线图默认带十字准星 + tooltip**（这是默认，不是可选）
- **命中区域要比 mark 本身大**（细线尤其需要）
- **数据表视图**：每个图都应能切换到「看数据」模式——这是无障碍硬要求（`App.tsx` 的
  `ViewToggle`）。逐期数值、发布日与修订状态**不一定只能在这里读到**：十字准星的 tooltip
  同样输出这四样（`lineOption.ts` 的 `formatter`）。数据表是其中**唯一不依赖鼠标悬停**的
  通道，这才是它不可省的理由

### 6.6 反模式清单

- ❌ **双轴图**（两种量纲共用一张图）——宏观经济图表最常见的错误："把 CPI 和 M2 放一张图"。
  两个 y 轴之间没有任何可解释的关系，读者会看到虚假的相关性。正确做法：两个图、小倍数、
  或指数化到同一基期。（这条原在 §6.1，该节删除时唯一保留下来的规则）
- ❌ **彩虹色 / 循环使用色相**——序列再多也**不生成新色相**，到上限就折叠为「其他」或改用分面（§6.2 的「固定顺序，按序分配，绝不循环」）
- ❌ **颜色跟随排名而非实体**——筛选后幸存序列不得换色
- ❌ **用颜色单独表达状态或涨跌**（必须有图标 + 文字）
- ❌ 每个数据点都标数值——选择性直接标注关键点
- ❌ 3D 效果、阴影、渐变填充

### 6.7 深浅色模式

- 深浅色**各自独立取阶**，不是自动反转
- 深色模式的值必须**针对深色表面重新验证**——`index.css` 的
  `@media (prefers-color-scheme: dark)` 里那套就是验证过的深色色值，不是把浅色值调暗得来的
- **跟随系统已实现**（`styles/index.css` 的 `prefers-color-scheme`）。**手动切换尚未实现**（没有设置页）；`charts/theme.ts` 已经在监听 `documentElement` 的 `data-theme` 变化，将来加开关时不必改图表代码
- 在 `styles/index.css` 里用 `@theme inline` 统一定义 CSS 变量，图表主题与 UI 共用同一套令牌

### 7.3 指标详情页（Detail）

```
┌─────────────────────────────────────────────────────────────┐
│ 规模以上工业增加值：当月同比          cn.ind_prod.yoy       │
├─────────────────────────────────────────────────────────────┤
│  2.7 %           2026-08                                    │
│                  发布日 2026-09-15                          │
├─────────────────────────────────────────────────────────────┤
│ 规模以上工业指年主营业务收入 2000 万元及以上的工业企业。……  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│           主图表（折线图，带十字准星 tooltip）              │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│ [图表] [数据表]                        共 55 个期间         │
│ ◇ 标记为 1—2 月合并发布，非单月值   ← 序列中存在时才显示    │
└─────────────────────────────────────────────────────────────┘
```

要点：
- **Hero 数字是全页焦点**（44px），右侧是期间与发布日
- **口径说明常驻**，不藏进 tooltip——这是本产品相对同类工具的核心差异化
- **图表 / 数据表一键切换**：图表给走势，数据表给逐期数值、发布日与修订状态。
  切换控件与「共 N 个期间」在**图表下方**一行
- 修订值在数据表的「状态」列标注
- `merged` 期间在图上用菱形点标出，**并在切换行下面再补一行文字说明**——形状与文字两条通道，
  满足 §6.2「绝不单靠颜色」。这行只在**该序列真的有 `merged` 行时**才渲染
  （如 `cn.ind_prod.yoy` 有 5 条；`cn.cpi.yoy` 一条都没有，就不会出现）

> 时间范围选择、口径切换器、导出 CSV、关注、跳转原始页面这些控件**都还没有**。
> 其中**时间窗查询数据层已经支持**——`getSeries` 接 `from` / `to`（§5.2），渲染端目前只传了 `id`，
> 缺的只是控件。真正还缺数据模型的是「同一指标的多口径关联」。

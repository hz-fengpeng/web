## 8. 非功能需求

| 维度 | 要求 |
|---|---|
| **启动时间** | 冷启动到可交互 < 2s |
| **切换指标** | < 100ms（本地 SQLite） |
| **内存** | 常驻 < 400MB（ECharts 实例必须在卸载时 `dispose()`，见 §12 风险 11） |
| **打包产物体积** | `release/mac-arm64/中国宏观经济指标.app` 解压后 **289 MB**。`target: dir` 只产 `.app`、不产压缩安装包，体积主要来自 Electron 运行时。**原定「< 120MB」的目标未达成** |
| **首次启动** | 开窗前复制一次 135 KB 的库文件，没有「等待初始化」这个状态 |
| **离线** | 应用根本不联网，天然离线 |
| **数据真实性声明** | ★ **界面必须常驻声明数据从哪来、有什么边界**，且声明与库中内容一致——数从哪来由构造保证（每次启动覆盖内置库，§3.2.0），数是不是都有采集记录由 §14.4 那条不变量守着（§12 风险 0） |
| **无障碍** | 键盘可达全部功能；图表有表格视图替代；状态/涨跌不单靠颜色；对比度达标 |
| **国际化** | 仅中文。没有 i18n 框架，文案直接写在组件里 |
| **错误处理** | 任何失败都不应导致白屏；降级到已有数据并提示 |
| **日志** | 主进程把 `error` / `warning` 级日志转发到终端。未接落盘日志库 |

## 9. 安全与合规

### 9.1 数据合规

- ✅ **库里的数值是真实统计数据**，经东方财富 / 国家统计局 / 国家外汇管理局的公开渠道采集
  （[§14](08-真实数据采集.md)）。版权风险低，但**引用时以官方发布为准**
- ⚠️ `released_at`（发布日）是**按惯例推算**的，不是官方发布时刻（§14.6）——任何按它排的日历
  都不能被当作官方发布安排
- ⚠️ 各指标的「口径说明」记录的是**真实统计口径**；它不描述库中数据的新旧，也不替代官方口径文件
- ⚠️ 本项目为**个人自用、不对外分发**（§1.4）。若这一前提改变（分发、商用、提供 API），需重新做合规评估

> 原方案里还有一整节采集合规（只采官方源、标注来源、采集礼仪、限流约束）——采集层在 M1c
> 整体删除后一并去掉了；后来以 `fetcher/` 的形式重新接入，那一节的约束在 §14.1/§14.2
> 以「开发机手动跑、遇到访问控制不绕过、没有源就留空」的形式重新成立。

### 9.2 应用安全

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`（强制）
- 渲染进程 CSP `connect-src 'none'`——从架构上杜绝渲染进程直连网络
  （⚠️ **只对打包产物成立**：`npm run dev` 下 HMR 需要把 `connect-src` 放宽到 localhost，见 §5.1）
- preload 仅通过 `contextBridge` 暴露白名单方法，不暴露任何 Node 原语
- 所有外部链接用 `shell.openExternal()` 打开系统浏览器，绝不在应用内导航
- 禁用 `window.open`、`webview` 标签

## 10. 工程化与交付

### 10.1 npm scripts

**当前实际存在的**（以 `package.json` 为准）：

```jsonc
{
  "dev":       "node scripts/dev.mjs",
  "setup:electron": "node scripts/dev.mjs --setup",
  "build":     "npm run typecheck && electron-vite build",
  "preview":   "electron-vite preview",
  "typecheck": "tsc --noEmit -p tsconfig.node.json && tsc --noEmit -p tsconfig.web.json",
  "test":      "vitest run",
  "dist:mac":  "npm run build && electron-builder --mac --arm64"
}
```

**目标形态，尚未创建**（依赖的工具也尚未安装——写在这里是备查，不要照着敲）：

```jsonc
{
  "lint":           "eslint . --max-warnings 0",
  "test:e2e":       "playwright test"
}
```

> ⚠️ `typecheck` 拆成了 node/web 两个 project——渲染进程与主进程的 `lib` / `types` 不同，
> 合在一个 `tsconfig.json` 里会让 DOM 类型漏进主进程（反之亦然）。

**打包配置在 `electron-builder.yml`**（M1d 新增）。其中 `extraResources` 一节是**必需的**：

```yaml
extraResources:
  - from: resources/macro.db
    to: macro.db        # 落到 Contents/Resources/macro.db
```

应用不生成数据，全部读这个文件；主进程按 `process.resourcesPath/macro.db` 找它。
漏了这节，dev 下一切正常而打出来的 `.app` 启动即失败（§12 风险 14）。
`mac.target` 定的是 `dir`——本机自用、不分发，直接出可双击的 `.app`，跳过签名与公证（决策 5）。

失败；②「`resetToBundled` 忘了关连接」→ 只有重置正例失败。否则「测试通过」可能只是因为它
压根没在测东西。（上一轮同样验过三条，其中「不覆盖」现在反过来写成了「覆盖」。）

**M2a 当时的验证记录（以下 42 例是历史数量）：**

| 项 | 实际 |
|---|---|
| 用例总数 | 42 例全绿（`npm test`）：数据层 25 + 图表 17 |
| 图表用例 | `src/renderer/src/charts/lineOption.test.ts`，17 例 |

图表用例里几条不是走过场的：

- **色值一律用哨兵值**（`surface: '#010203'`、`accent: '#131415'` 这种），不用真实色号。然后序列化整个 option，
  断言里面出现的每一个 `#rrggbb` 都来自传入的 tokens——用真实色号的话，把色值硬编码进 `lineOption.ts` 也照样绿。
- **`x 轴缺月`那条是 D3 的哨兵**：断言 `2025-12` 与 `2026-02` 两个点的间隔是硬编码的
  59 天。改成类目轴会立刻失败。
- **成对断言**：只查 `xAxis.splitLine.show === false` 的话，把水平网格也一起关掉照样绿，
  所以同时断言 `yAxis.splitLine.lineStyle.color` 等于注入的哨兵色。
- **负时区一段**在 `America/New_York` 下跑，且带一条对照断言
  （`expect(new Date(jan1).getFullYear()).toBe(2025)`）——否则时区没生效时这条是空转的。

**一个特别的反例测试。** 「不关连接就覆盖会让重置静默失效」这条结论不是推理出来的，是实测的
（`copyFileSync` 就地截断写、inode 不变，旧连接仍持有自己的 WAL，覆盖后 SQLite 把它重放回去，
内置文件被整个盖掉）。`bootstrap.test.ts` 里有一条测试**故意断言这个错误做法的行为**。
它是那段警告的实证：哪天 SQLite 行为变了，这条会失败——那时该重新审视注释，而不是把测试改绿。

**两条从 M1a 继承下来的纪律：**

1. **fixture 必须是真实抓取的样本，绝不手写。** 手写的 HTML 会「正好符合我以为的结构」，把假设固化成测试。`rowspan` 那个 bug 就是这么潜伏下来的——手写样本里没人会去写 `rowspan` 角格。（联网 fixture 已随采集层删除，重接时须重新抓取。）
2. **守一个具体 bug 的断言必须成对，且其中一条要能区分「对的原因」和「错的原因」。** 例：断言失业率取到 `5.3` 不够（错误实现也取得到），必须同时断言「取 `同比增长（%）` 列返回 `no-value`」——这一对才排除了列错位。
   - 已删除的种子测试里的例子：哨兵值必须落在生成器**不可能**产生的区间。一开始用 `0.8` 当哨兵，结果 CPI 的合理值域里本来就有 `0.8`，测试假通过。
   - **当前（M1d）的同类例子**：「不关连接就覆盖会让重置静默失效」这条，正例（`resetToBundled`）与**反例**（故意跳过 close）成对存在。只有正例的话，把这个断言删掉照样绿；反例的存在才证明「必须先关连接」不是一句想当然的话。

### 10.6 开发启动自检

`npm run dev` 改为 `scripts/dev.mjs`：检查当前平台可执行文件与版本，缺失时调用 Electron 官方安装器，
确认安装完整后才启动 electron-vite；若仅 `path.txt` 缺失则恢复路径，不重新下载。
`ELECTRON_RUN_AS_NODE` 只从子进程环境移除，不修改用户 shell 或系统环境。
`npm run setup:electron` 单独完成补装，支持 `HTTPS_PROXY` / `HTTP_PROXY`，不把本机代理地址写死到源码中。

实际通过当前 7897 代理完成安装并运行 `Electron --version`，结果 `v44.4.5`。5173 被占用时 Vite 自动选择 5174，
这是正常的开发端口回退，不影响桌面应用。

# 中国宏观经济指标

macOS 桌面应用，把**按官方统计口径定义**的宏观经济指标集中到一个可交互、口径可追溯的看板里。
Electron + React + TypeScript，本地 SQLite。

> ✅ **随包发布的 `resources/macro.db` 里是真实统计数据**：登记的 109 个指标里 23 个有值
>（P0 的 18 个，加 P1 的国债 1 年期 / 10 年期、美国 10 年期、由它们算出的中美利差、
> 铁路货运量当月同比），来自东方财富、国家统计局、国家外汇管理局、中国债券信息网、
> 新浪财经的公开数据；其余 86 个没有免费数据源，如实留空（界面显示「暂无数据」），**不编数**。
> 数是开发期用 [`fetcher/`](fetcher/README.md) 抓好后
> 随安装包发布的（[§14](docs/08-真实数据采集.md)），应用本身**完全不联网**。
> 界面不判断「这份库是真是假」——那套机制已整个删除。**每次启动都用内置库覆盖 userData
> 那份**（应用从不写 `observation`，覆盖不丢东西），所以打开时手上的库与随包发布的那一份
> 结构性地一致（[§3.2.0](docs/02-数据层.md)）。老用户手上那份旧库不用自己处理：一启动就被盖掉。

**完整设计与决策记录见 [docs/](docs/README.md)**（按主题分 7 篇，`§X.Y` 是稳定编号）。

## 运行

```bash
npm install
npm run dev          # 自动检查 Electron 安装后进入开发模式（HMR）
npm run setup:electron # 单独检查/补装 Electron 可执行文件
npm run build        # 类型检查 + 构建
npm run dist:mac     # 打包成未签名的本地 .app（约 289MB）
```

`npm run dev` 自动检查 Electron 的可执行文件与版本，缺失时调用官方安装器补装，
完整安装不会再次下载；安装中断只丢失 `path.txt` 时会直接恢复该文件。
启动子进程前会清除 `ELECTRON_RUN_AS_NODE`，可直接从 VS Code 集成终端运行。

若下载需要本机代理，先执行（当前机器提供的代理端口为 7897）：

```bash
HTTPS_PROXY=http://127.0.0.1:7897 npm run setup:electron
npm run dev
```

补装使用 Electron 安装器的文件校验；下载代理只用于补装，应用数据仍完全离线。

## 测试

```bash
npm test             # 79 例，全部离线
npm run test:py      # 140 例，抓取器（fetcher/）的 Python 侧，同样全部离线
npm run typecheck    # tsc --noEmit，node/web 两个 project 各跑一遍
```

测试与源码同目录，覆盖数据库迁移与恢复、折线/对比图、浏览数据语义、CSV 与导出 IPC 边界。
抓取器的解析与写入语义由 `fetcher/tests/` 覆盖（unittest，输入是录制的样本，不碰网络）。
没有持久化 E2E 或 CI 配置，本机 `npm test`、`npm run test:py` 与 `npm run build` 是自动化关口。

## 数据与合规

- 数据是**真实统计数据**，来自东方财富、国家统计局、国家外汇管理局、中国债券信息网、
  新浪财经的公开渠道，随项目提交。
  发布日 `released_at` 是**按惯例推算**的，不是官方发布时刻（[§14.6](docs/08-真实数据采集.md)）——
  引用时以官方发布为准。
- 采集是**开发期**动作，跑在 [`fetcher/`](fetcher/README.md) 里，不属于应用；
  遇到访问控制不绕过，没有源就留空。
- 应用仅本地运行、**个人自用、不对外分发**（[§1.4](docs/01-产品定义.md)）。不签名、不公证、不做自动更新。
- 渲染进程的 CSP 是 `connect-src 'none'`，**应用根本不联网**（[§9.2](docs/05-工程化与交付.md)）。

## 当前进度

M0–M2a 的数据层与折线图基础上，已补齐以下功能（内置库为**真实统计数据**：
109 个登记指标 / 10251 条观测，其中 23 个指标有值（18 个 P0 + 5 个 P1）、86 个留空）：

- **经济概览**：12 个核心 KPI、关注视图、GDP / CPI / PMI / 社零 / M2 / 社融 6 张趋势图，均可切换到数据表。
- **指标库与详情**：分类、P0/P1/P2 筛选、搜索、排序、关注、快捷/自定义时间窗、工业增加值同比/环比切换、分页数据表、历史修订。
- **对比分析**：最多 3 个指标，同口径、单位、频率和季调状态守卫；共用单轴与对齐数据表。
- **发布日历**：按推算的发布日浏览、按分类/日期筛选、查看修订发布事件，不推测未来安排。
- **导出与数据管理**：当前时间窗 CSV / PNG、全部观测 CSV（含历史修订）、数据覆盖情况、带确认的重置。
- **设置与恢复体验**：系统/浅色/深色主题、默认时间窗、关注与偏好本地保存，错误重试、空状态、焦点样式与渲染错误兜底。

CSV 带 UTF-8 BOM、口径、单位、状态、修订号与出处声明；PNG 带标题、口径说明与出处声明。
声明是 `src/shared/provenance.ts` 里的一个常量（数据来源 + 推算发布日说明），没有按性质分支——
**导出文件会脱离应用**，那一行是它唯一的来历，所以它由导出侧自己写上，调用方改不掉。
导出通过原生保存对话框选择位置，取消不写入文件。

## 指标数据扩充

指标定义共 **109 个**，P0 / P1 / P2 分别为 **23 / 38 / 48**，覆盖 9 个主题、4 种频率——
清单、口径与层级全部定义在 `src/shared/indicators.ts`（不再有单独一篇目录文档）。
P1/P2 里有 31 个省级 GDP 累计同比、5 个贸易伙伴的进出口、5 类社零分项，以及人口、城镇化率、
基尼系数、国际收支主要账户与分项、外债、收益率节点和计算指标。

**定义 ≠ 有数据**：109 个指标**全部**在库里都有观测行，但只有 23 个有值——
P0 的 18 个，加上 P1 接进来的国债 1 年期 / 10 年期、美国 10 年期、中美 10 年期利差
（由前两条算得）与铁路货运量当月同比。其余 86 个在库里是 `value=NULL` /
`status='missing'` 的空行，界面如实显示「暂无数据」。
哪些指标取哪一列、哪 86 个为什么留空，写在
[`fetcher/macro_fetcher/mapping.py`](fetcher/macro_fetcher/mapping.py)：
三条表（`RULES` 22 / `DERIVED` 1 / `UNSOURCED` 86）**每条留空都带理由**，
并以 `(a)` 上游不发布 / `(b)` 渠道取不到 / `(c)` 计算指标缺输入 标出类别——
P1/P2 的留空集中在统计局公开库的挑战页、渠道只有累计口径、渠道没有分项这几个卡点上，
逐条清单见 [fetcher/README.md](fetcher/README.md)。

**旧版本的示例库不再有任何升级路径**：`catalog.ts` 那套「给旧库追加指标定义、保留用户改值」
是给合成库用的，已随假数据逻辑一起删除。老用户手上那份文件不用自己处理——**每次启动都被
内置库覆盖**（[§3.2.0](docs/02-数据层.md)）。代价是用户在库里手改过的值不会保留；这个应用
从不提供改值的入口，也没有别的东西写这张表，所以那份文件本来就只是内置库的运行期副本。

刷新数据跑 [`fetcher/`](fetcher/README.md)（开发期工具，不在应用里运行）：

```bash
cd fetcher && ./.venv/bin/python -m macro_fetcher --tier P0 --dry-run   # 先看差异
```

覆盖范围、写入语义（修订 vs 换库、1—2 月合并）与「装了旧版本的用户怎么拿到真实数据」
（一启动就被内置库覆盖）见 [fetcher/README.md](fetcher/README.md) 与 [§14](docs/08-真实数据采集.md)。
